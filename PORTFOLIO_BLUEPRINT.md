# Amit Rai / Brandzoo Media Portfolio Blueprint

## 1. Strategic Positioning

**Primary brand promise:** Amit Rai helps businesses turn paid media, SEO, funnels, and creative strategy into measurable growth.

**Visitor reaction to engineer:** "This is not a generic freelancer site. This feels like a premium growth consultant and agency founder who understands performance, brand, analytics, and conversion."

**Positioning pillars**

- Trust: verified results, testimonials, client logos, certifications, transparent process.
- Authority: founder-led strategy, performance dashboards, case-study breakdowns, blog insights.
- Expertise: clear service specialization across Meta Ads, Google Ads, SEO, funnels, lead generation, GMB, app marketing, UGC, and social growth.
- Creativity: cinematic visual system, 3D marketing objects, polished interaction design, premium art direction.
- Results: ROAS, CPL, lead volume, conversion lifts, before/after graphs, campaign dashboards.

**Recommended site identity**

- Personal brand: Amit Rai
- Business brand: Brandzoo Media
- Core line: Digital Marketing Specialist, Performance Marketer, Founder & CEO @ Brandzoo Media
- Hero headline: "Performance Marketing Built For Brands Ready To Scale"

## 5. Motion & Interaction System

### Motion Principles

- Motion should communicate precision and momentum, not chaos.
- Animate metrics and proof points when they enter the viewport.
- Keep 3D always tasteful: no heavy gimmicks over readability.
- Respect reduced motion preferences.

### Libraries

- Framer Motion / Motion for React: component transitions, hover states, scroll reveals.
- GSAP + ScrollTrigger: cinematic pinned sections, timeline sequencing, parallax.
- Three.js + React Three Fiber: hero background, floating 3D analytics objects, interactive objects.
- Drei: useful R3F helpers where appropriate.

### Motion Patterns

- Hero intro: staggered fade/slide, role switcher, metric count-up.
- Mouse-follow lighting: radial gradient following cursor on hero and cards.
- 3D cards: subtle transform on pointer movement.
- Scroll reveal: section title, cards, charts.
- Dashboard charts: draw lines and bars on entry.
- Page transitions: soft fade and lift.
- Admin: minimal motion, fast and utilitarian.

## 6. Recommended Tech Architecture

### Stack

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- Framer Motion / Motion
- GSAP
- Three.js
- React Three Fiber
- Supabase Postgres
- Supabase Auth
- Supabase Storage
- Zod
- React Hook Form
- TanStack Table for admin tables
- Recharts or Nivo for dashboard charts
- TipTap or MDX editor for blog/rich content
- Resend or SMTP provider for inquiry notifications

### Rendering Strategy

- Public pages: Server Components by default.
- Interactive visual modules: isolated Client Components.
- 3D hero: dynamically imported with SSR disabled.
- CMS data: fetched server-side with cache tags.
- Admin pages: authenticated server-side layouts plus client-side editors.
- Forms: Server Actions for mutations where possible.
- Webhooks/uploads: Route Handlers.

### Performance Strategy

- Lazy-load 3D scenes below or behind hero.
- Provide lightweight CSS/Canvas fallback for low-power devices.
- Compress and transform media via Supabase image transformations or Next image optimization.
- Use `prefers-reduced-motion` to disable heavy cinematic animation.
- Keep homepage JS islands small.
- Use dynamic imports for GSAP-heavy sections.

## 10. Security & Admin Access

### Supabase Security

- Use Supabase Auth for admin login.
- Enable Row Level Security on all CMS tables.
- Public users can read only `published` content.
- Admin users can manage content.
- Storage buckets should have strict policies:
  - public read only for published media
  - authenticated write only for admins
  - signed URLs for private documents if needed

### Admin UX

- Login protected by middleware.
- Dashboard shows:
  - total case studies
  - published blog posts
  - new inquiries
  - missing SEO fields
  - certifications expiring soon
- Every content form includes:
  - draft/publish switch
  - preview
  - SEO tab
  - media picker
  - autosave-ready structure

## 13. Backend Architecture

### Supabase Clients

- `server.ts`: request-scoped server client for authenticated reads.
- `browser.ts`: client-side admin interactions that require user session.
- `admin.ts`: service-role client used only in Route Handlers or Server Actions that require elevated access.

Important implementation rule: initialize clients lazily in functions so builds do not crash when env vars are unavailable during static analysis.

### Server Actions

- `createCaseStudy`
- `updateCaseStudy`
- `deleteCaseStudy`
- `publishCaseStudy`
- `createBlogPost`
- `updateBlogPost`
- `uploadMediaMetadata`
- `submitInquiry`
- `updateSeoSettings`

### Route Handlers

- `/api/upload`: signed upload flow or server-side upload handler.
- `/api/webhooks/supabase`: optional content revalidation.
- `/api/contact`: use only if Server Actions are not preferred for the contact form.
